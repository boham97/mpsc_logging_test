## 해석

- 실제 실행은 `REF=0 tools/cmp_all.sh 10000` (Quill/spdlog 원본은 이 세션에서 실행 권한이 막혀 logx 만 측정). 원본과 나란히 재려면 `tools/save_result.sh cmp_bench_ref tools/cmp_all.sh`.
- 조건은 Quill `hot_path_latency`·`backend_throughput`, spdlog `bench.cpp` 와 같다 (자세한 대응은 `examples/cmp_bench.c` 머리 주석). logx 는 `-O2`, 튜닝 안 한 노트북(SMT 켜짐, isolcpus 없음).
- **hot path 지연 (p50 / p99.9, ns)**

  | 로거 | numbers 1T | numbers 4T | string 1T | string 4T |
  |---|---|---|---|---|
  | `LFLOG` | 99 / 417 | 140 / 699 | 44 / 389 | 72 / 364 |
  | `LFLOG_TEXT` | 319 / 748 | 504 / 1252 | 131 / 612 | 264 / 775 |
  | async | 258 / 860 | 410 / 959 | 117 / 530 | 206 / 683 |
  | sync buffered | 254 / 1989 | 418 / 6484 | 116 / 1910 | 210 / 6378 |

  Quill README 공개값(i5-12600 4.8GHz, 튜닝된 머신)은 numbers p50 6~8ns, spdlog 271/557ns. 머신이 달라 직접 비교는 못 하지만 `LFLOG` 는 Quill·fmtlog 계열보다 한 자릿수 느리고 spdlog 보다는 빠른 쪽이다. 차이의 출처로 보이는 것: 공유 MPSC 큐의 CAS(Quill 은 스레드별 SPSC), 1KB 고정 슬롯, 호출마다 rdtsc+TID+레벨 기록.
  - numbers 가 string 보다 `LFLOG` p50 이 2배 높은 이유는 아직 확인 안 함 (double 인자 vs 문자열 인자 외에 차이 없음).
- **처리량 (400만 줄, flush 까지)**: `LFLOG` 2.99, `LFLOG_TEXT` 3.60, async 3.70, sync buffered 3.53 M줄/s. Quill 공개값 6.44, spdlog 2.57. `LFLOG` 는 로깅 스레드의 `%g`(snprintf) 포맷팅이 상한이다 — 같은 로거가 `%d` 하나뿐인 spdlog 메시지는 약 10 M줄/s.
- **spdlog bench.cpp (25만 줄)**: `LFLOG_TEXT` 4스레드 18.1 M/s 가 최고, async·sync buffered 는 4스레드에서 5.5~6.8 M/s 로 떨어짐(뮤텍스 경쟁), sync direct 0.8~0.9 M/s. level-off 는 모두 0.5~0.9 G/s (호출당 1~2ns).
