# perf: LFLOG 포화 시 CPU 시간 분포

- 날짜: 2026-11-02 14:25
- 코드: `97bef09`과 같은 코드 (당시 커밋 전 작업 트리: TSC, busy_poll, TID 인라인). 접두어는 `snprintf`
- 환경: AMD Ryzen 5 7430U with Radeon Graphics, 12 CPU (6코어 × 2), Linux 6.12.0-211.16.1.el10_2.0.1.x86_64, clocksource=tsc
- 명령: `perf record -q -e cycles:u --call-graph dwarf,16384 -F 4999 -o drv.data ./drv 8 200000` (`drv` = 지금의 `examples/lf_drv.c`)
- 분석: `perf report`(아래 1~4), 로깅 스레드 호출 스택 분류는 `perf script -F tid,ip,sym --inline` 출력을 스크립트로 집계(아래 5)

## 해석

- 로깅 스레드(64261)가 전체 샘플의 45.7%다. 그중 99%가 `render_record`(인라인)다.
- 로깅 스레드 샘플 2899개를 호출 스택으로 나누면, 접두어 `log_format_prefix → snprintf`가 45.1%, 메시지 `out_printf → vsnprintf`가 23.8%다. 스택에 `snprintf`/`vsnprintf`가 있는 샘플이 69.1%이고, 포맷 문자열 해석(`strchr`, `next_arg`, `parse_spec` 등)이 약 22%다.
- 호출 스레드 8개는 포함 시간의 94%(51.0/54.2)가 `enqueue_or_wait` 안의 `sched_yield`다. `encode_record`는 1.5% 미만이다.
- 결론: 병목은 로깅 스레드의 `snprintf` 기반 포맷팅이고, 호출자는 빈 슬롯을 기다리며 CPU를 쓴다. 이후 [접두어 직접 변환](2026-11-02_154000_prefix_direct.md)으로 확인했다.
- `perf report` 헤더의 "Samples: 21K"는 `--tid` 필터 전 값으로 보인다. `perf script`로 센 로깅 스레드 샘플은 2899개다.
