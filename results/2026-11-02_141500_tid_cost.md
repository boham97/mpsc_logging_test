# TID를 인자로 넘기면 빨라지는가

- 날짜: 2026-11-02 14:15 무렵
- 코드: 세 변형: old = `00da87e`의 `log_common`(함수 호출), inl = 당시 작업 트리(인라인 TLS 읽기, 지금 코드), arg = inl에서 `lflog_record`에 `tid` 인자를 추가한 측정용 사본
- 환경: AMD Ryzen 5 7430U with Radeon Graphics, 12 CPU (6코어 × 2), Linux 6.12.0-211.16.1.el10_2.0.1.x86_64, clocksource=tsc
- 명령: 측정용 프로그램 `tb.c`(TID 조회 2억 회 + 1000줄 버스트 × 300번, 5ms 휴식, 중앙값), `enc.c`(`encode_record` 1000만 회 × 7번 중 최솟값, `taskset -c 3`). 둘 다 세션 스크래치패드에서 빌드
- 주의: 이 출력은 파일로 남지 않아 세션 출력에서 옮겨 적었다.

## 해석

| | TID 조회 | `encode_record` |
|---|---|---|
| old (함수 호출) | 1.16 ns | 37.9~38.3 ns |
| inl (인라인 TLS) | 0.24 ns | 37.4~37.8 ns |
| arg (인자로 넘김) | 0 | 37.0~37.5 ns |

- 인자로 넘겨 줄어드는 건 함수 호출 1ns 정도로, 측정 편차 수준이다.
- `LFLOG` 전체 호출(첫 번째 표)은 50~170ns이고 실행마다 ±30ns 흔들려서 세 변형의 순위가 매번 바뀐다. 1ns 차이는 보이지 않는다.
- 결론: API는 그대로 두고 인라인 TLS 읽기만 유지한다.
