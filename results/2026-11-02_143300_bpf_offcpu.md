# bpftrace: 스레드별 시스템 콜·off-CPU 시간 (LFLOG)

- 날짜: 2026-11-02 14:33 (1차), 14:57 (2차)
- 코드: `97bef09`과 같은 코드 (당시 커밋 전 작업 트리). 접두어는 `snprintf`, `busy_poll` 꺼짐
- 환경: AMD Ryzen 5 7430U with Radeon Graphics, 12 CPU (6코어 × 2), Linux 6.12.0-211.16.1.el10_2.0.1.x86_64, clocksource=tsc
- 명령: `sudo bash run_bt.sh` → `bpftrace lf.bt -o bt_sat.txt -c "./drv 8 200000"`, `bpftrace lf.bt -o bt_burst.txt -c "./drv 8 50000 1000"`
- 스크립트: 당시 `lf.bt` = 지금의 `tools/lf_offcpu.bt`에서 합계를 µs로 자르던 버전
- 주의: `@yield_us`는 시스템 콜마다 `ns / 1000`을 정수로 잘라 더해서 1µs 미만인 `sched_yield`가 0으로 들어갔다. 같은 일을 하는 스레드가 수천 µs와 30만 µs대로 갈리는 것은 이 잘림 때문이다. 횟수(`_n`)와 `write`·off-CPU 합계는 영향이 작다. 저장소의 `tools/lf_offcpu.bt`는 이후 ns로 더하도록 고쳤다.

## 해석

TID 역할: `write`를 하는 TID가 로깅 스레드, 실행 내내 futex에 있는 TID가 `pthread_join` 중인 메인 스레드, 나머지 8개가 호출 스레드다.

| | 1차 | 2차 |
|---|---|---|
| **쉬지 않고** (`8 200000`) 실행 시간 (메인 스레드 futex) | 0.87초 | 0.94초 |
| 로깅 스레드 `write` | 175회, 21.4ms | 175회, 22.8ms (2.4%) |
| 로깅 스레드 futex / off-CPU | 0회 / 0.47ms | 0회 / 0.51ms |
| 호출 스레드 `sched_yield` 합계 | 약 370만 회 (줄당 2.3회) | 약 399만 회 (줄당 2.5회) |
| 호출 스레드 off-CPU | 0.1~0.8ms (65248만 4.9ms) | 0.05~0.5ms (70051만 5.3ms) |
| **버스트** (`8 50000 1000`) 로깅 스레드 `write` | 44회, 6.0ms | 44회, 6.0ms |
| 로깅 스레드 futex | 1회 | 1회 |
| 호출 스레드 `sched_yield` | 스레드당 약 1만 회 | 스레드당 약 1.1만 회 |
| 호출 스레드 off-CPU | 약 103ms (2ms 휴식 50번) | 약 103ms |

- 로깅 스레드는 한 번도 잠들지 않고 CPU 위에 있다. 디스크 쓰기는 2.4%다. 병목은 CPU 위의 포맷팅이다([perf](2026-11-02_142500_perf_lf_drv.md)).
- 호출 스레드는 거의 선점되지 않고, 큐가 가득 차 `sched_yield`를 반복한다. 대기 루프 한 바퀴는 약 1.8µs(0.87초 ÷ 스레드당 약 47만 회).
- futex 깨우기는 시작 시점 외에 없다. 원인이 아니다.
- `lf_drv 8 50000 1000`은 초당 400만 줄을 넣어 당시 로깅 스레드 처리량(약 300만 줄/s)을 넘으므로 실제 버스트가 아니다.
