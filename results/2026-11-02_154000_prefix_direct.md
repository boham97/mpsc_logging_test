# 접두어 직접 변환 전후 (bench)

- 날짜: 2026-11-02 15:38~15:42
- 코드: old = `97bef09` (접두어 `snprintf`), new = `c95baff`와 같은 코드 (당시 커밋 전)
- 환경: AMD Ryzen 5 7430U with Radeon Graphics, 12 CPU (6코어 × 2), Linux 6.12.0-211.16.1.el10_2.0.1.x86_64, clocksource=tsc
- 명령: old/new `bench`를 조건마다 번갈아 3번: `8 200000`, `8 50000 1000`, `1 50000 1000`. 모든 실행에서 결과 파일 검증 OK

## 해석

결과 요약은 README "접두어 직접 변환 적용 전후" 표다.

- `LFLOG` 쉬지 않고 8스레드: 처리량 1.73~1.84 → 3.28~3.35M줄/s, p50 2.9~3.1 → 0.83µs, 10µs 이상 6.1~6.4 → 2.9~3.0%. p99/p99.99는 그대로다.
- `LFLOG` 버스트 8스레드: 로깅 스레드가 넣는 속도를 따라잡아 p99.99가 43~133 → 4.2~5.9µs.
- 호출자가 접두어를 만드는 모드(`LFLOG_TEXT`, async, sync buffered)는 p50이 100~200ns 줄었다.
- 쉬지 않고 쓸 때 `LFLOG_TEXT` p99가 0.9~1.0 → 1.3~1.5µs로 늘었다. 원인은 [경쟁 계측](2026-11-02_154600_contention.md)에서 슬롯 번호 CAS 경쟁 증가로 확인했다.
- async의 10µs 이상 비율 증가(1.3~1.5 → 1.5~1.6%)는 같은 계측에서 편차로 확인했다.
