## 해석

`%g` 직접 변환(`log_format_g`) 적용 후 `fmt_bench`. "현재" 열은 로거가 지금 쓰는 경로(꾸밈 없는 `%g`는 `log_format_g`)다. 고속 경로(`직접`, `직접+캐시`)도 `%g`를 처리하도록 바꿨다.

- `%g` 하나: `snprintf` 149~169ns → 직접 14~17ns (9~12배). 같은 크기 정수를 `snprintf("%zu")`로 찍는 것(32ns)보다도 빠르다.
- cmp 처리량 메시지 한 줄(`render_record` 현재 경로): 327ns([이전](2026-11-18_155017_fmt_bench_g.md)) → 174ns. `%g`를 `%zu`로 바꾼 대조군(176ns)과 같아졌다. 포맷팅만 본 상한은 3.06 → 5.75 M줄/s.
- 남은 비용은 정수 `%zu` 두 개의 `snprintf`와 포맷 해석이다. 직접 변환 + 해석 캐시까지 하면 93ns(10.7 M줄/s)다.
- 구현: double 을 m×2^q 로 풀고, 128비트 정수 연산으로 유효숫자 6자리를 정확하게 반올림한다(동률이면 짝수). 1.4e-17 ≤ |v| < 2.4e21 밖과 비정규수·inf·nan 은 `snprintf`로 넘긴다.
